# R09-B · 설명을 입력칸 위로

`DESIGN.md` **11.4** 를 읽어라. 작은 수정이지만 근거가 거기 있다.

지금 `Field` 의 세로 순서는 **레이블 → 입력칸 → 설명 → 오류**다.
설명이 입력칸 아래라서 **다 입력한 뒤에 읽게 된다.** "예: 010-1234-5678" 같은
형식 안내는 그 시점에 쓸모가 없고, 사용자는 틀린 뒤에야 보게 된다.

바꿀 순서: **레이블 → 설명 → 입력칸 → 오류**

## 1. 할 일

`field.tsx` 에서 `description` 을 렌더하는 `<div>` 를 `cloneElement(child, …)` 호출
**앞으로** 옮겨라. 그게 전부다.

**`aria-describedby` 의 순서는 바꾸지 마라.** 지금처럼 오류가 먼저다 —
급한 것을 먼저 읽어줘야 한다. 눈으로 보는 순서와 읽어주는 순서가 다른 것은
의도이고 11.4 에 그렇게 적혀 있다. 주석으로 한 줄 남겨라.

## 2. 스토리로 못 박아라

`기본` 스토리 play 에 **세로 순서 단언**을 추가하라. 기존 단언은 지우지 마라.

```
설명의 bottom ≤ 입력칸의 top   (설명이 위에 있다)
입력칸의 bottom ≤ 오류의 top   (오류가 아래에 있다)
```

`getBoundingClientRect()` 값을 숫자로 떠서 비교하라.
`getComputedStyle` 은 라이브 객체이니 쓰지 마라.

`aria-describedby` 가 여전히 `오류 설명 기존것` 순서인지도 단언하라
(이미 25행에 있다 — 그대로 통과해야 한다).

## 3. 하지 마라

- `aria-describedby` 순서 변경
- `form.css` 의 다른 규칙 변경 (순서는 DOM 으로 바꾸고 `order` 속성을 쓰지 마라 —
  DOM 순서와 시각 순서가 어긋나면 키보드·스크린리더가 꼬인다)
- 다른 컴포넌트·토큰·문서 수정
- 커밋 · 푸시
