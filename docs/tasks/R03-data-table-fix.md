# R03-A 후속 · 정렬 추론 교정과 메모이제이션

`DataTable` 구현은 통과했다. 검수에서 두 가지를 고친다.
**아래 두 항목만 고친다. 다른 동작·스타일·API 를 바꾸지 마라.**

---

## 1. 컬럼 정렬을 선언 가능하게 만든다 (API 변경)

### 문제

`data-table.tsx` 의 `numericIds` 는 런타임 데이터에서 "숫자 컬럼"을 추론한다.
디자인 시스템에서 정렬은 **데이터가 아니라 컬럼 작성자가 결정할 일**이다.

지금 구조에서 실제로 틀리는 경우:
- 주문번호를 `number` 로 저장하면(`20241190841`) 우측 정렬되고 금액용 최소 너비 128px 을 받는다.
- 금액을 서버에서 문자열(`"1248500"`)로 받으면 좌측 정렬되고 고정폭 숫자가 적용되지 않는다.
- 첫 비어있지 않은 값이 우연히 숫자인 혼합 컬럼이 전부 우측 정렬된다.

### 할 일

`DataTableProps` 에 선택적 prop 을 추가한다. 기존 `exportValue` 와 같은
"컬럼 id → 값" 맵 패턴을 쓴다 (v9 `meta` 등록은 하지 마라 — 이미 그 이유로 `exportValue` 를 골랐다).

```ts
/** 컬럼별 정렬. 지정하지 않은 컬럼은 데이터로 추론한다(숫자면 'end'). */
align?: Record<string, 'start' | 'end' | 'center'>;
```

규칙:
- `align[columnId]` 가 있으면 **그 값이 추론을 무조건 이긴다.**
- 없으면 기존처럼 추론한다. 추론 결과가 숫자면 `'end'`, 아니면 `'start'`.
- `'end'` 인 컬럼에만 `tabular` + `text-right` + `data-table-numeric`(금액 최소 너비 128px)을 적용한다.
- `'center'` 는 `text-center`. 최소 너비는 텍스트 기본값(80px)을 쓴다.
- 헤더의 정렬 아이콘 배치(`ml-auto`)도 같은 기준을 따른다 — 지금은 `numericIds` 를 보고 있다.
- 선택 컬럼(`SELECTION_COLUMN_ID`)은 기존처럼 가운데 고정이며 `align` 의 영향을 받지 않는다.

## 2. 추론 비용을 낮추고 메모이제이션한다

### 문제 (실측값)

```
const value = table.getCoreRowModel().rows.map((row) => row.getValue(column.id))
  .find((item) => item !== null && item !== undefined);
```

컬럼마다 **전체 행을 배열로 복제한 뒤** 첫 값을 찾는다.
행 1,000 × 컬럼 10 기준 렌더 1회당 `getValue` **10,000회**, 길이 1,000 배열 10개 할당.
측정 결과 **0.120 ms/렌더** (단축 구현은 0.001 ms).
이 컴포넌트는 행 호버·선택·정렬마다 리렌더되고, 현재 파일에 `useMemo` 가 **0개**다.

### 할 일

- `.map().find()` 를 `.find()` 로 바꿔 첫 비어있지 않은 값에서 즉시 멈춘다. 중간 배열을 만들지 않는다.
- 추론 대상 행을 **앞에서 최대 20행까지만** 본다. 20행 안에 비어있지 않은 값이 없으면 `'start'` 로 둔다.
  (20행을 다 비워둔 컬럼의 정렬을 데이터로 맞히는 것은 의미가 없다.)
- 결과를 `React.useMemo` 로 감싼다. 의존성은 실제로 영향을 주는 것만 —
  컬럼 id 목록, `align` prop, 그리고 데이터 식별값. `table` 객체 자체를 의존성에 넣지 마라
  (매 렌더 새 객체일 수 있다).
- 같은 파일의 `startWidth` / `endWidth` 처럼 매 렌더 재계산되는 값 중,
  **의존성이 명확하고 계산이 반복되는 것만** 추가로 메모이즈한다.
  억지로 전부 감싸지 마라 — 의존성 배열이 틀리면 버그가 되는 쪽이 더 나쁘다.

메모이제이션 후에도 `align` 을 바꾸면 즉시 반영되어야 한다.

## 3. 스토리 추가

`data-table.stories.tsx` 에 `정렬지정` 스토리를 하나 추가한다.
- 주문번호를 **숫자 타입**으로 담은 데이터를 쓴다 (추론이 틀리는 조건을 재현).
- `align={{ orderNo: 'start', count: 'center' }}` 로 추론을 덮어쓰는 것을 보여준다.
- 같은 데이터로 `align` 없는 버전과 있는 버전을 **위아래로 나란히** 배치해 차이가 보이게 한다.
- `parameters.docs.description.story` 에 왜 선언이 추론을 이겨야 하는지 한두 문장.
