# R43 · 단계 표시 (Steps)

근거: `docs/research/ui-coverage-review.md` P2. 상품 등록·캠페인 생성·입점 신청 같은 여러 단계 폼. 지금은 AI 가 숫자 원과 선을 직접 그린다.
0.3.1 후보. **버전은 올리지 마라.**

---

## 1. 부품 (이름은 제안)

`Steps`: `steps`(라벨·선택 설명) · `current`(0부터 또는 1부터 — 근거와 함께 하나로) · 단계별 상태 `complete | current | upcoming | error` 계산과
덮어쓰기(오류 단계) · 선택 `onStepClick`(완료된 단계로만 돌아가기). **폼 상태·검증·이동 버튼은 앱 몫** — 표시만

- 구조: `ol` 목록, 현재 단계 `aria-current="step"`, 각 단계 이름에 상태가 들어간다("2단계 가격 입력, 진행 중"). 완료·오류는 아이콘 + 글자(색만 금지)
- 가로 배치 기본. 좁은 폭(측정해서 경계를 정해라)에서는 "2 / 4 · 가격 입력" 요약으로 — 가로 넘침 없음
- 클릭 가능한 완료 단계는 버튼(키보드), 나머지는 정적. 다음 단계로 건너뛰기는 안 된다
- FormFlow 와 함께 쓰는 예시(단계마다 FormFlow 하나) — 연결 방식은 문서·MCP 규칙으로

## 2. 문서·MCP·스토리

- DESIGN 폼 절에 "여러 단계 폼" — 언제 단계로 나누는가(5칸 이상·서로 다른 주제), 단계 이동 시 포커스(새 단계 제목으로)
- MCP intent + keywords("단계", "스텝", "진행 단계", "여러 단계 폼", "1단계 2단계") + FormFlow·TaskProgress(장기 작업 진행과 다르다) dont/related
- 스토리: 기본 4단계 · 첫·중간·마지막 · 오류 단계 · 완료 단계 클릭 · 긴 라벨 · 좁은 폭 · 다크 · 상품 등록 3단계 조립(FormFlow). Primary 깨끗하게
- MCP 크기: 상한 회귀 단정을 실측 + 여유 300 이하로. 카탈로그 90KB·목록 24KB·상세 6KB·토큰 80KB·규칙 8KB 안(R42 에서 응답 단위 예산으로 바뀐다).
  카탈로그가 90KB 를 넘게 되면 지침을 줄이지 말고 멈춰서 보고하라
