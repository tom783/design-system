## 결정 근거 — 토큰 상속

우리 색은 CSS 변수다. 라이트/다크 전환과 브랜드 교체가 변수 값 교체로 끝난다.

- **SVG**: `fill="var(--brand-600)"` 로 변수를 직접 받는다. JS 코드가 **0줄**이다.
- **Canvas**: 픽셀을 찍는 시점의 색을 JS 가 알아야 한다. `getComputedStyle` 로 변수를
  읽어 차트 설정에 주입하고 재렌더하는 배선을 **모든 테마 변경 지점에** 걸어야 한다 —
  OS 테마 변경(`prefers-color-scheme` 리스너), 사용자 토글, 브랜드 교체, 차트 인스턴스마다.
  빠뜨린 한 곳이 "다크모드에서 차트만 밝은" 버그가 된다.

Canvas 가 불가능한 것이 아니라, 그 배선을 영구히 소유해야 한다는 것이 비용이다.

## visx 의 배포 주기에 대해

visx 최근 배포가 5개월 전으로 recharts(4개월, 239릴리스)보다 느리다. 다만 visx 는
스케일·축·도형 프리미티브의 얇은 래퍼라 표면이 작고 바뀔 것이 적다. 실제 계산은
`d3-scale`·`d3-shape`가 하고 그쪽은 11일 전에도 배포됐다.

반대로 말하면 **visx 가 멈춰도 잃는 것이 적다** — 차트 코드는 우리 저장소에 있고
visx 는 스케일 함수와 path 생성기만 제공한다. 프리미티브 접근의 위험 분산이다.

## ECharts 탈출구 조건 (Q3 승인 시 DESIGN.md 로 승격)

visx 가 약한 단 하나의 영역은 **10만 포인트 이상 실시간 렌더**다. SVG 는 포인트마다
DOM 노드를 만들어 수만 개에서 느려진다. 그런 화면이 생기면 ECharts 를 그 화면에만
쓰고, 토큰을 JS 로 주입하는 배선을 한 곳에만 만든다. 현재 그런 화면은 없다.
