# R40b · 달력 날짜 색과 모드별 빠른 선택

날짜 셀에 지정한 색보다 내부 `Button variant="ghost"`의 자체 글자색이 우선하여
이번 달·이웃 달이 모두 `text-secondary`로 보였다. 일반 날짜 버튼에 직접
이번 달 `text-primary`, 이웃 달 `text-tertiary`를 적용한다. 선택·오늘·범위 중간의
기존 상태 스타일과 이웃 달 날짜의 선택 가능 여부는 유지한다.

## 대비 측정

생성된 `docs/research/tokens.json`의 실제 sRGB 값을 WCAG 상대휘도 공식으로 계산했다.
달력 팝오버의 `bg-surface`가 배경이다. 아래는 토큰 값의 대비 측정이며 브라우저
렌더 실측 결과가 아니다. 판정에는 반올림 전 값을 사용했다. 새 토큰은 없다.

| 테마 | 이번 달 `text-primary` | 이웃 달 `text-tertiary` | 배경 `bg-surface` | 이웃 달 대비 | 4.5:1 |
|---|---|---|---|---|---|
| 라이트 | `#262222` | `#6A6260` | `#FFFFFF` | 5.9510097569046625:1 | 통과 |
| 다크 | `#F7F6F5` | `#B6ADAB` | `#1A1817` | 8.049633808759557:1 | 통과 |

## 빠른 선택

| 모드 | 목록 |
|---|---|
| range | 오늘 · 최근 7일 · 이번 달 · 지난 달 |
| single 날짜 | 오늘 · 어제 |
| single + time | 오늘 · 내일 |

단일 날짜는 기간의 끝날을 대신 고르지 않고 달력 날짜를 계산한다. 날짜 이동은
DST·월말·연말에도 달력 연산을 사용한다. 기준일은 누르는 시점에 계산하며 `today`가
주어지면 그 값을 쓴다. 시각의 보존·첫 선택 09:00·시각 모드의 열린 레이어는 유지한다.

DESIGN 날짜 절에 목록을 명시했다. MCP DatePicker의 기존 규칙에는 빠른 선택 목록
설명이 없어 수정하지 않았다. 규칙 수와 카탈로그 80,286바이트는 유지한다.

## 하네스 변경

`date-time-render-verify.mjs`에 다음 단정을 추가했다. 실행은 사용자가 한다.

- 세 모드 각각 라이트·다크에서 일반 날짜(11/1·11/2)는 `text-primary`,
  이웃 달(12/5)은 `text-tertiary`이고 두 색이 다르다. computed 글자색과 팝오버
  배경으로 대비 4.5:1 이상을 검사하며 측정값은 `results.json`에 저장한다.
- 세 모드의 빠른 선택 목록을 순서까지 검사한다. 날짜 single에서 어제·오늘을
  누른 결과와 닫힘도 검사한다.
- 이웃 달 날짜를 날짜 single·시각 single에서 선택할 수 있고 시각을 보존한다.

옛 목록을 전제한 기존 단정 변경은 **한 곳**이다.
`달력 날짜만 바꾸면 13:30 유지·빠른 선택도 시각 유지` 검사에서
`지난 달 → 2026-10-31 13:30`을 `내일 → 2026-11-16 13:30`으로 바꿨다.
기존 range의 빠른 선택 단정은 그대로다.
