# R04 후속 · TrendBand 의 y축 기준선

렌더 검증에서 발견했다. **내 지시서가 축 기준 규칙을 적지 않은 것이 원인이다.**
당신은 안전한 기본값(0 포함)을 골랐고 그 판단 자체는 합리적이었다.
다만 선 차트에서는 그 선택이 신호를 죽인다.

**이 항목만 고친다. 다른 동작·API·스타일을 바꾸지 마라.**

## 1. 문제 — 실측

`trend-band.tsx` 가 도메인에 0 을 강제한다:

```ts
const low = Math.min(0, ...points.map((d) => Math.min(d.low, d.value)));
const high = Math.max(0, ...points.map((d) => Math.max(d.high, d.value)));
```

주문 데이터(값 980~1,402 · 밴드 760~1,660)에서:

| 축 | 데이터가 차지하는 세로 비율 |
|---|---|
| 0 기준 (현재) | **52%** |
| 데이터 프레이밍 | **86%** |

헤드리스 렌더 스크린샷에서 추세선이 상단에 눌려 거의 평평하게 보인다.
그 차트의 `aria-label` 은 "11월 8일 980건에서 11월 14일 1,284건으로 증가했습니다"라고
말한다 — **글과 그림이 어긋난다.**

## 2. 규칙 (DESIGN.md 7.5.3 규율 8 로 확정됨)

- **막대 · 0까지 채우는 영역** → 0 기준 필수. 채워진 길이가 크기를 인코딩하므로.
- **선 · 상하한 밴드** → 데이터 프레이밍. 선은 크기가 아니라 *변화*를 인코딩하므로.

`TrendBand` 는 후자다. 밴드는 상한과 하한 사이만 칠하고 축 바닥까지 내려가지
않으므로, 0 이 아닌 기준선을 써도 면적이 크기를 속이지 않는다.

## 3. 할 일

`TrendBandProps` 에 추가한다:

```ts
/** y축 기준. 'auto'(기본) = 데이터 범위로 프레이밍, 'zero' = 0 포함, 또는 직접 지정 */
yDomain?: 'auto' | 'zero' | [number, number];
```

- `'auto'`(기본): 밴드가 있으면 `[min(low), max(high)]`, 없으면 `[min(value), max(value)]`
  를 기준으로 **위아래 각각 8% 여유**를 두고 `nice: true` 를 적용한다.
- `'zero'`: 지금 동작(0 포함)을 유지한다.
- 튜플: 그대로 쓴다. 뒤집혀 들어오면(hi < lo) 정렬해서 쓴다.
- **값이 전부 같은 경우**(변화 0)에도 깨지지 않아야 한다. 지금의 `high === low ? low + 1`
  방어는 유지하되, 그 경우 선이 플롯 세로 가운데에 오게 한다.
- **값이 음수인 경우**에도 동작해야 한다(반품 증감 등). 0 을 강제하지 않으므로
  음수 구간만 있는 데이터도 정상 프레이밍되어야 한다.

## 4. 스토리 추가

`charts.stories.tsx` 에 `추이밴드_축기준` 하나를 추가한다.
**같은 데이터**를 `yDomain="zero"` 와 `yDomain="auto"`(기본)로 **위아래 나란히** 놓아
차이가 한눈에 보이게 한다. `parameters.docs.description.story` 에
어느 경우에 어느 쪽을 쓰는지(규율 8) 한두 문장.

음수가 섞인 데이터로 `추이밴드_음수` 도 하나 추가한다 — 깨지지 않는 것을 보여준다.


도메인 계산을 순수 함수로 분리해 단위 테스트를 추가하라 —
`resolveYDomain(points, mode)` 형태. 최소 케이스: auto(밴드 있음/없음),
zero, 튜플, 뒤집힌 튜플, 값이 전부 동일, 전부 음수.
억지로 분리해 복잡해지면 하지 말고 판단해서 보고하라.
