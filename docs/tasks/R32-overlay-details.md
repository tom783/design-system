# R32 · 레이어 디테일 — 열리는 것들을 라이트·다크로 열어 본 결과

R31 의 화면 조립 훑기에서는 레이어가 닫혀 있었다. Select·행 액션 메뉴·DatePicker·Combobox·AlertDialog 를
실제로 열어 라이트·다크로 쟀다. **버전은 올리지 마라.**

---

## 0. 전제 — 내가 측정한 것 (1100×760, Pretendard 로드)

## 1. O1 · 막은 두 테마 모두 뒤를 어둡게

- 막 색을 본문 글자색에서 떼어 낸다. 어두운 기준색(예: 가장 어두운 중립색) + 테마별 불투명도. 다크는 이미 어두우므로
  더 짙게(근거를 적어라). 필요하면 토큰(`--overlay-scrim` 등)을 추가하고 생성기 검증을 통과시킨다
- 같은 막을 쓰는 곳 전부(Dialog·AlertDialog·MediaViewer popup 등)를 찾아 함께 바꾼다
- 측정 기준: 두 테마 모두 막을 얹은 뒤 캔버스 지점의 합성 휘도가 **원래보다 낮다**(어두워진다)

## 2. O2 · X 가 없으면 설명은 상자 폭을 다 쓴다

- AlertDialog(닫기 버튼 없음)의 제목·설명이 닫기 버튼 자리를 비우지 않는다. Dialog 에서 `showClose` 가 꺼진 경우도 같다
- 측정 기준: 닫기 버튼이 없을 때 설명 폭 = 상자 안쪽 폭(±1px)

## 3. O3 · Combobox 현재 옵션은 Select 처럼 배경으로

- 현재(키보드 활성) 옵션 표시를 Select 와 같게: 배경색, outline 없음. 고른 값의 체크 표시는 유지
- 팝오버 안 검색 입력의 포커스 표시가 팝오버 가장자리에 겹치지 않게 (안쪽 링이나 아래 경계 강조 등). **포커스는
  보여야 한다** — 표시가 사라지면 안 된다. 바꾼 방식과 이유를 DESIGN 포커스 절에
- MultiSelect 목록의 현재 옵션 표시도 같은지 확인하고 다르면 맞춘다
- 측정 기준: Combobox·Select·MultiSelect 현재 옵션의 계산 스타일(outline·배경)이 같다. 입력의 포커스 표시가
  팝오버 테두리 사각형 안쪽에 있다

## 4. O4 · 메뉴 글자 시작을 맞춘다

- 메뉴에 아이콘 항목이 하나라도 있으면 아이콘 없는 항목도 아이콘 자리만큼 들여 글자 시작을 맞춘다
  (`:has()` 같은 CSS 로 — 소비자 prop 을 늘리지 마라). 아이콘이 하나도 없는 메뉴는 그대로
- 측정 기준: 같은 메뉴 안 항목들의 글자 시작 x 가 ±1px

## 5. O5 · 떠 있는 레이어는 화면 가장자리에서 띄운다

- DatePicker 팝오버에 화면 가장자리 여백(충돌 여백). **Select·DropdownMenu·Combobox·MultiSelect·Popover 류 전부**를
  확인해 같은 값으로 맞춘다 (토큰 간격으로, 값과 근거를 적어라)
- 측정 기준: 오른쪽 끝 트리거에서 연 레이어의 오른쪽 여백 ≥ 그 값

## 6. O6 · 범위 중간은 "선택"으로 보이게

- 범위 중간 날짜 배경을 `--bg-selected`(선택된 행과 같은 의미 토큰, 라이트 brand-50 · 다크 brand-975)로.
  호버 배경과 달라야 한다
- 측정 기준: 범위 중간 배경 ≠ 호버 배경, 팝오버 대비 수치를 라이트·다크로 보고(목표: 현재 1.18·1.12 보다 분명히 큼)

## 7. 하네스

`docs/qa/` 에 레이어 디테일 하네스(또는 R31 디테일 하네스 확장) — 위 측정 기준을 라이트·다크 둘 다로 단언한다.
레이어는 **실제 포인터 클릭**으로 연다(R24 함정: 합성 click 으로는 일부 레이어가 안 열린다). 기존 단정의 기대값은
고치지 말고, 흔들릴 후보를 목록으로 보고해라.
