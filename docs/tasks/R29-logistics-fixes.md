## 1. G1 · 데이터에서 빠진 행은 선택에서 자동 해제한다 (사용자 결정)

사용자가 "자동 해제"를 골랐다. **보이는 것만 처리한다**가 보장이다.

- `data` 가 바뀌어 현재 행 id 에 없는 선택은 빠진다. 제어형이면 `onSelectedIdsChange(교집합)`,
  비제어면 내부 상태를 줄인다. **교집합이 같으면 호출하지 않는다**(무한 루프·불필요 렌더 방지)
- **`state` 가 `loading`·`error` 일 때는 줄이지 않는다** — 재조회 중 빈 목록이나 일시 오류로 선택이
  날아가면 안 된다. 필터 결과가 실제로 비면(`empty`) 선택도 비는 게 맞다
- `hasMore`·`onLoadMore` 로 행이 **덧붙는** 경우는 교집합이 그대로라 영향 없음을 확인
- 헤더 체크박스: 보이는(현재 data) 행 기준으로 전체/일부/없음을 계산한다. 지금의 indeterminate 는
  TanStack `getIsSomeRowsSelected()` 가 선택 상태의 키 수를 세서 생긴 버그다
- DESIGN.md 표 절에 정책 한 단락: 무엇이 언제 빠지고 왜(물류 일괄 처리의 안전), 로딩·오류 예외
- MCP DataTable 규칙(소비자 말, 120자 이하): 필터 등으로 data 에서 빠진 행은 선택이 자동 해제되므로
  앱은 `selectedIds` 를 그대로 일괄 작업에 쓰면 된다는 것

## 2. G2 · 범위 입력은 자기 값을 다 보여준다

- 범위 모드에서 입력이 **플레이스홀더 전체와 범위 값 전체를** 자르지 않는 최소 폭을 갖는다.
  단일 모드 폭은 바꾸지 마라
- 고정 px 를 박을 거면 근거(측정값)를 주석에. 폰트·숫자 폭에 따라가는 단위(`ch` 등)를 쓸 거면 실제로
  들어가는지 하네스로 증명해라 — `ch` 는 `0` 의 폭이라 `Y`·`M`·`D` 플레이스홀더는 더 넓을 수 있다

## 3. G3 · 툴바에서 DatePicker 입력이 다른 컨트롤과 같은 줄에 선다

오류 예약 줄 때문에 루트가 58px 이다. 폼에서 오류가 떠도 흔들리지 않게 하려는 예약은 필요하다.
그런데 DatePicker 를 `Field` 안에 넣으면 **Field 도 오류 공간을 예약**한다 — 이중 예약인지 먼저 재라.

원하는 결과(측정 가능한 기준):
1. `items-center` 툴바에서 DatePicker **입력** 중심이 38px 형제 컨트롤 중심과 ±1px
2. `Field` 안: 오류 공간이 하나다. 잘못된 날짜를 입력하면 오류가 보이고 아래 칸이 밀리지 않는다
3. `Field` 밖: 잘못된 날짜 오류가 보이고 읽힌다(`aria-describedby`·`aria-live`), 형제 컨트롤을 밀지 않는다

선호 방향: DatePicker 는 자기 오류 줄을 예약하지 않는다. Field 안이면 Field 의 오류 자리를 쓰고,
Field 밖이면 입력 아래에 레이아웃을 밀지 않게 띄운다. **소비자 prop 을 늘리지 않는 쪽**을 먼저 시도하고,
Field 와의 연결이 크게 번지면 멈추고 무엇이 걸리는지 보고해라.

## 4. G4 · 중립 계열 색 토큰과 쓸 수 있는 색 목록

- 토큰 추가: 상태 칩의 neutral 과 짝이 되는 **중립 상태 색** (`--status-neutral-fg`·`-bg` 를 기본안으로.
  이름을 바꾸면 이유를 보고). 라이트·다크·OS 테마 모두 정의, 생성기 대비 검증 통과 —
  차트 면·선은 비텍스트 3:1 기준(DESIGN §7.5, 원칙 "색")
- StatusChip neutral 이 새 토큰을 쓰게 할지는 시각 변화가 없을 때만 (있으면 보고)
- `06-charts.mdx` 에 **계열 색으로 쓸 수 있는 CSS 변수 목록**(다섯 개)과 "목록 밖 이름은 그려지지 않고
  검게 보인다"를 적는다. CompositionArea 소비자 규칙(MCP)에도 한 줄
- 잘못된 변수를 런타임에 잡는 장치는 만들지 마라 (이번 범위 밖)

## 7. 검증

`npm_config_offline=true pnpm verify` 와 **`node docs/qa/mcp-client-verify.mjs .qa-shots/mcp-client-verify`**
(verify 에 없다. 매니페스트를 바꾸면 반드시 — R28 에서 이걸 빠뜨려 push 가 막혔다).

하네스 (작성만):
- **G1**: DataTable 스토리 — 필터 토글이 있는 선택 표. 전체 선택 → 필터 변경 → `onSelectedIdsChange`
  가 교집합으로 한 번 불린다, 앱 쪽 개수 = 툴바 개수 = 보이는 체크 수, 헤더가 indeterminate 가 아니다.
  `state='loading'` 으로 바꿨다 돌아와도 선택 유지. 같은 data 로 다시 렌더하면 호출 0회. 행 덧붙이기에도 유지
- **G2**: 범위 값 입력 후 입력 `scrollWidth <= clientWidth + 1`, 플레이스홀더도 (같은 계산 스타일 span 으로)
- **G3**: 툴바 스토리(MultiSelect · Select · DatePicker · Button)에서 입력 중심 ±1px. Field 안 오류 시 아래 칸 위치 불변
- **G4**: 차트 스토리 하나가 중립 계열을 쓴다. 그 계열 면의 계산된 `fill` 이 검정(`rgb(0, 0, 0)`)이 아니고
  범례 색 칸 배경이 투명이 아니다. 라이트·다크 둘 다
- 기존 하네스 전부 그대로 통과

함정: `Blob.text()` 는 BOM 을 떼어 낸다(바이트로 재라). 폭은 canvas 가 아니라 같은 계산 스타일의 요소로 재라.
