# 도그푸딩 3 · 물류관리 — 출고 관리 (Next.js App Router)

main(`7f8ce8b`, 0.3.1 후보)으로 만든 팩을 소비자로 설치해 출고 관리 화면을 만들었다.
앞 두 회차가 건드리지 않은 **대량 데이터 · 일괄 처리 · 바코드 스캐너 입력**을 겨냥했다.

- Next 16.4.6 · React 19.3.1 · App Router · **pnpm 엄격 모드, `@s2life/ui` 하나만 직접 설치** (R27)
- 만든 것: 출고 지시 목록 5,000건(센터 MultiSelect · 상태 Select · 기간 DatePicker 필터, 선택 → 일괄 출고
  → TaskProgress → toast, CSV 내보내기) · 운영 지표(BulletRow · CompositionArea) · 스캔 검수(FormFlow)
- 검증: chrome-headless-shell CDP, 콘솔 오류 0건

## 통과한 것

| 확인 | 결과 |
|---|---|
| ui 하나만 설치 (pnpm 엄격) | 설치 · `next build` 타입 검사 통과. 앱에서 `@s2life/tokens/*` 직접 해석은 안 됨(의도대로) |
| 가상화 5,000건 | DOM 행 **20개**, `aria-rowcount=5000`, 뷰포트 480px |
| 필터 | 이천센터 → `aria-rowcount=1250` |
| 전체 선택 | 5,000건 선택 (보이는 행만이 아니라 전체) |
| CSV | 5,001줄(헤더 포함) · BOM `EF BB BF` · `"골판지 상자 (대, ""특수"" 규격)"` 이스케이프 · 파일명 `출고지시.csv` |
| 숫자 열 | 자동 오른쪽 정렬 + `tabular-nums` |
| 일괄 출고 | TaskProgress(`progressbar` 0 → 완료) → 성공 토스트 |
| 오류 토스트 | `duration: 3000` 을 줬지만 5초 뒤에도 남고 닫기 버튼 있음 — **R28 규칙대로** |
| 스캔 흐름 | 바코드 입력 + Enter → 상품 Combobox → Enter 로 열고 선택 → 수량 → Enter → 사유 라디오 → Enter → 메모(Enter 는 줄바꿈) → Cmd+Enter 제출 → **바코드 칸으로 복귀·비움** (`restartOnSubmit`) |
| 잘못된 수량 | 오류 문구 + 수량 칸으로 포커스 |

스캐너 작업 흐름은 손대지 않고 그대로 쓸 수 있었다. FormFlow 계약(R16·R18)이 실전에서 맞았다.

**측정 실수 기록:** 처음에 CSV BOM 을 "없음"으로 쟀다. `Blob.text()` 가 UTF-8 디코딩에서 BOM 을
떼어 내기 때문이다. 바이트(`arrayBuffer`)로 다시 재니 있었다.

## 찾은 간극

### G1 · 필터를 바꾸면 화면에 없는 행이 선택된 채 남는다 — 중대

이천센터 필터에서 전체 선택(1,250건) → 필터를 부산센터로 바꿨다.

| | 표시 |
|---|---|
| 앱의 일괄 버튼 (`selectedIds.length`) | **"선택 1,250건 출고 처리"** — 누르면 화면에 없는 이천 건을 처리한다 |
| DataTable 툴바 | "0개 선택" |
| 헤더 체크박스 | **일부 선택(indeterminate)** — 보이는 행 중 체크는 0개 |
| CSV 내보내기 | 현재 보이는 부산 1,250건 |

DataTable 과 앱이 서로 다른 선택 수를 말한다. 헤더의 "일부"는 TanStack `getIsSomeRowsSelected()` 가
현재 행이 아니라 선택 상태의 키 개수를 세서 생기는 **버그**다. DESIGN.md 에는 데이터가 바뀔 때 선택을
어떻게 다루는지 정책이 없다. 소비자로서 나는 이 경우를 생각하지 못했다.

### G2 · 날짜 범위 입력이 고른 값보다 좁다 — 중대

`DatePicker` 루트가 `min-w-[240px]` 이라 달력 버튼·간격을 빼면 입력이 **198px**.
범위 값 `2026-11-10 ~ 2026-11-30` 은 **216px**, 플레이스홀더는 **238px** 가 필요하다(같은 계산 스타일로 측정).
고른 기간이 잘려 보인다. 단일 날짜에는 충분한 폭이라 범위 모드에서만 드러난다.

### G3 · DatePicker 가 툴바의 다른 필터보다 10px 위에 놓인다 — 보통

루트 높이가 58px(입력 38 + 오류 예약 줄 20)이라 `items-center` 툴바에서 입력 중심이 458, 다른 컨트롤은 468.
오류 줄 예약은 폼에서 레이아웃 흔들림을 막는 장치인데 필터 툴바에서는 정렬을 깬다.

### G4 · 차트 계열에 쓸 중립 색이 없고, 틀리면 말없이 검게 그린다 — 보통

물류 상태는 대기·피킹·포장·출고완료·보류다. 차트 계열에 쓸 수 있는 상태 색은
`--status-{info,warning,success,danger}-fg` 넷뿐이라 "대기"에 줄 중립 색이 없다.
`var(--status-neutral-fg, var(--text-muted))` 로 추측했고 둘 다 없는 이름이었다 →
**면적이 검은색, 범례 색 칸은 빈칸**, 경고 없음. DESIGN.md §7.5 는 "계열 색이 더 필요하면 토큰을 추가한다"
고 이미 말한다. 쓸 수 있는 계열 색 목록도 문서에 없다(스토리 코드에서만 보인다).

### G5 · CSV 가 화면 라벨이 아닌 원본 값을 내보낸다 — 보통

상태 열이 화면에는 "대기"인데 CSV 에는 `waiting`. 금액의 쉼표를 피하려고 원본을 쓰는 설계이고
`exportValue` 로 바꿀 수 있다. 그런데 그 사실을 알려 주는 지침이 없다. 엑셀을 받는 현업에게 영문 코드가 간다.

### G6 · 추측한 `meta: { numeric: true }` 가 조용히 무시된다 — 기록만

숫자 정렬은 DataTable 이 데이터로 자동 판단해 결과는 맞았다. TanStack `ColumnMeta` 가 열려 있어 아무
키나 통과한다. 정렬을 강제하려면 DataTable 의 `align` prop 이다.

### G7 · 디자인 글꼴이 소비자 앱에 오지 않는다 — 중대 (R29 수정 뒤 발견)

토큰은 `--font-sans: 'IBM Plex Sans KR', …` · `--font-mono: 'IBM Plex Mono', …` 인데 **글꼴을 불러오는 곳이
Storybook 의 `preview-head.html`(Google Fonts 링크) 하나뿐**이다. 패키지 CSS 에 `@font-face` 가 없고 README·문서에
로드 방법이 없다. 물류 앱의 `document.fonts` 에 로드된 웹폰트 **0개** — 시스템 대체 글꼴로 그려졌다.
같은 플레이스홀더가 Storybook 185px, 앱 238px 로 잰 이유다. 도그푸딩 1·2 도 같은 상태였을 것이고 아무도 몰랐다.
번들할지(용량·라이선스 OFL·자체 호스팅) 문서로 안내할지는 결정이 필요하다.

**처리 (R30, 사용자 결정):** 기본 글꼴을 **Pretendard** 로 바꾸고, 패키지에는 넣지 않고 로드 방법을 문서로
안내한다(`npm install @s2life/ui pretendard` + 동적 서브셋 CSS import). Storybook 도 같은 import 로 바꿨고,
배포 리허설이 안내대로 한 앱(기본·Tailwind)에서 `Pretendard Variable` 이 실제로 로드되는지 검사한다.
숫자는 Pretendard `tabular-nums`(0–9 폭 차 0px)로 통일해 앱이 불러올 글꼴은 하나다. 글꼴 폭에서 나온 수치를
다시 재니 금액 칸이 128px 로는 12px 모자라 140px 로 고쳤다.

## 반영 결과 (R29, 0.3.1 후보)

수정본 팩을 같은 앱에 다시 설치해 쟀다. 앱의 중립 계열은 문서대로 `var(--status-neutral-fg)` 로 바꿨다.

| | 수정 전 | 수정 후 |
|---|---|---|
| G1 필터 변경 뒤 | 앱 버튼 1,250건 · 툴바 0 · 헤더 일부 | **앱 버튼 0건 · 툴바 0 · 헤더 없음** |
| G2 범위 입력 | 198px | **264px** (값 216 · 플레이스홀더 238 모두 들어감) |
| G3 툴바 중심 | 날짜 458 · 나머지 468 | **모두 458**, 오류 없을 때 오류 줄 높이 0 |
| G4 대기 계열 | 검정, 범례 빈칸 | `rgb(83, 76, 75)`, 범례 같은 색 |
| G5 | 지침 없음 | MCP DataTable 규칙에 `exportValue` |

검수에서 고친 것: Codex 가 DatePicker 오류 문구를 한 줄에 넣으려고 "올바른 날짜를 입력하세요"로 줄였는데,
오류가 날 때는 입력에 글자가 있어 플레이스홀더가 안 보인다 — 고치는 법이 사라졌다. 같은 계산 스타일로 재서
형식·순서를 담고도 한 줄에 드는 문구로 바꿨다(범위 272px ≤ 286px, 단일 194px ≤ 220px).
새 하네스(도그푸딩 3, 24건)의 스토리·가정 오류 4건(스토리 순서, play 누락, 툴바 폭, 빈 표의 헤더 체크박스)도 고쳤다.
