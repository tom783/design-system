# R37b · 파일 업로드 보정 — 실측으로 찾은 6건

R37 하네스 12/13 · 문서 56/56 · MCP 응답 대조(기존 110개 바이트 동일, 추천 1순위 444개 동일).
실제 이미지 파일을 CDP 로 주입해 채운 상태를 라이트·다크·420px 로 봤다. 버전은 올리지 마라.

| # | 실측 | 고칠 것 |
|---|---|---|
| 1 | 드롭존 빈 영역 클릭 → `input.click` 0회(하네스 "Enter·Space·클릭" 의 4번째). 드롭존 `div` 에 클릭 처리가 없고 가운데 버튼만 연다 | 드롭존 빈 영역 **포인터 클릭**도 선택 창을 연다. 안쪽 버튼·삭제 버튼 클릭이 두 번 열리지 않게. 키보드는 지금처럼 버튼(드롭존 div 를 포커스 가능하게 만들지 마라 — 중첩 상호작용). 비활성이면 아무것도 안 한다 |
| 2 | CSS 클래스가 `file-upload-*` — 접두어 없음. 소비자 앱 클래스와 충돌한다 | 모두 `ds-file-upload-*`. (loading·data-table·state·media-viewer·thumbnail·avatar 의 기존 39개는 다음 라운드에서 한꺼번에 — 이번엔 손대지 마라) |
| 3 | Field 오류 상태에서 드롭존 점선과 **안쪽 "파일 선택" 버튼 테두리가 둘 다 빨갛다** — 이중 표시 | 오류 테두리는 드롭존만. 버튼은 보통 테두리(`aria-invalid` 는 버튼에 그대로 — 보조기기용) |
| 4 | 대표 이미지: 미리보기가 16:9 `width:100%` 라 드롭존 폭 전체(실측 약 820×460)를 차지하고 "바꾸기"·"삭제" 가 그 아래로 밀려 640px 화면 밖 | 미리보기는 **최대 폭 320px**(16:9 비율 예약 유지). 넓으면 미리보기 오른쪽에 파일명·크기·상태와 [바꾸기][삭제] 한 줄, 좁으면 아래로. 가로 넘침 없음 |
| 5 | 업로드 중 항목: 파일명 줄 바로 아래 진행률 라벨이 "상세컷.png 업로드" — **파일명이 화면에 두 번** | 진행 막대의 접근성 이름에는 파일명을 유지하되 화면에는 반복하지 않는다(퍼센트는 보인다). ProgressTrack 공개 API 는 늘리지 마라 |
| 6 | 스토리 "여러파일"·"대표이미지" 가 **빈 상태로만** 시작해 채운 모습을 볼 수 없다. "업로드실패" 썸네일은 16바이트 가짜 PNG 라 깨진 이미지 아이콘 | 두 스토리는 실제로 그려지는 작은 이미지(스토리 안에서 canvas 로 만든 PNG 등)로 **채운 상태**에서 시작(진행 중·완료·실패 섞어서). 업로드실패도 실제 이미지. Primary(사용법)는 지금처럼 깨끗하게 |

## 하네스 (`file-upload-render-verify.mjs` — 실행은 내가 한다)

- 1: 기존 단정 그대로 통과(드롭존 빈 영역 클릭 = 4번째 `input.click`). 안쪽 버튼 클릭 1회 = `input.click` 1회
- 2: 단위 테스트 — `file-upload.css` 의 클래스 선택자는 전부 `ds-` 로 시작(공개 `.sr-only`·`.tabular` 제외)
- 3: Field 오류에서 드롭존 경계색 = 위험 토큰, 버튼 경계색 = 기본 버튼 경계(라이트·다크)
- 4: 대표 이미지 선택 후 미리보기 폭 ≤ 320, [바꾸기]·[삭제] 가 900×640 뷰포트 안, 420px 에서 가로 넘침 0
- 5: 업로드 중 항목의 보이는 텍스트에 파일명이 한 번만, progressbar 접근성 이름에는 파일명 포함
- 6: 채운 스토리의 모든 썸네일 `img.naturalWidth > 0`
