# 폼 만들기

값과 검증 내용은 앱에서 관리하고, Field가 레이블·설명·오류·접근성 배선을 맡도록 조립합니다.

<Intent name="Field" />

```tsx
<Field label="수취인" description="주문서에 인쇄됩니다" error={error} required>
  <Input value={recipient} onChange={event => setRecipient(event.target.value)} />
</Field>
```

## 하단 고정 액션 줄

등록·편집 페이지의 취소·저장(과 수정의 삭제)은 FormActionBar 한 줄로 폼의 마지막 자식에 둡니다. AppShell 본문 바닥에 고정되고, 저장 중·저장하지 않은 변경·오류 N개(반복 입력 줄의 묶음 오류 포함)를 같은 자리에서 보여 줍니다. sticky div와 음수 여백으로 직접 만들지 않습니다. 옆 패널·대화상자는 DialogFooter를 그대로 쓰고 순서(취소 → 주요 버튼 오른쪽 끝)와 상태 문구 규칙만 맞춥니다. 화면 배치는 <DesignLink section="19.5">DESIGN.md §19.5</DesignLink>를 확인하세요.

## 반복 입력 줄

출고 품목·상품 옵션처럼 같은 칸 묶음(1~4칸)을 여러 줄 입력받으면 FieldList를 씁니다. 줄마다 Card·테두리 상자를 만들지 않습니다. 넓은 폭(부품 폭 640px 이상)은 열 머리를 한 번만 쓰고 줄마다 입력칸만 놓으며, 좁은 폭은 줄 머리와 칸 레이블로 쌓습니다. 입력 이름은 `품목 2 수량`처럼 부품이 붙입니다.

오류는 세 층입니다. 칸 오류는 열의 `error`, 칸 하나로 좁힐 수 없는 줄 오류(같은 품목 두 번)는 `rowError`, 목록 전체 오류(품목 0개·최대 초과)는 `error`로 목록 머리 아래 위험색 한 줄에 보입니다. 회색 보조 글자나 토스트로 대신하지 않습니다. FormActionBar `errorCount`에는 묶음 오류도 1개로 세고, `오류 N개`를 누르면 빈 목록은 추가 버튼, 아니면 첫 오류 칸으로 갑니다. 입력이 있던 줄을 지우면 5초 되돌리기 토스트가 뜨므로 화면에 Toaster를 둡니다. 규격은 <DesignLink section="11.10">DESIGN.md §11.10</DesignLink>를 확인하세요.
