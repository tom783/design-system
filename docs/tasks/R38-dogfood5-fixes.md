## 1. 본문 여백·페이지 머리 간격 (S1·S2)

실측: 본문 첫 글자가 본문 가장자리에서 56px(AppShell 24 + 앱 32), 페이지 머리 ↔ 툴바 약 60px(PageHeader 바깥 아래 여백 24 + 앱 gap 24).

- **PageHeader 의 바깥 여백(`margin-block-end`)을 없앤다.** 부품은 바깥 여백을 갖지 않는다 — 소비자의 gap 과 겹친다
  (Card 등 다른 부품과 같은 원칙). 아래 요소와의 간격은 페이지 배치가 준다
- MCP 규칙(소비자 말, R28 규칙: 금지어·120자):
  - AppShell: 본문 여백(24px, 좁으면 16px)은 내장되어 있다 — 페이지 루트에 padding 을 다시 주지 않는다. 화면 요소 사이는 gap 24px
  - PageHeader: 바깥 여백이 없다 — 아래 요소와의 간격은 페이지 배치(gap)로 준다
- 우리 예시(`docs/examples/app-shell.tsx` 등 PageHeader 를 쓰는 예시·스토리)를 같은 방식(gap 24 묶음)으로. 화면 간격이 지금과 같아야 한다(±1px)
- DESIGN §24 에 한 단락

## 2. 필터 줄의 Select 폭 (S3)

실측: SelectTrigger 기본이 칸 채우기(`w-full`)라 AI 가 `min-width` 만 준 카테고리 필터가 다음 줄 전체 폭이 됐다.
기본값은 바꾸지 마라(폼의 Field 안에서는 칸 채우기가 맞다). MCP Select 규칙 한 줄:
"필터 줄에서는 SelectTrigger 에 폭을 지정한다(기본은 칸을 채운다)". 우리 목록 화면 예시가 이미 그렇게 하고 있는지 확인하고, 아니면 맞춘다.

## 3. DataTable 툴바 (S4)

- 선택 기능이 없는 표(`selection` 미사용)에는 선택 상태 줄("N개 선택")을 그리지 않는다. 내보내기 버튼만 남는다
- 내보내기 버튼 라벨은 **짧은 동사구**. 부분 로드(`totalCount` > 로드된 행)면 "{N}건 내보내기", 상태 문구로 "전체 {M}건 중 {N}건"
  (페이지네이션·무한 스크롤 둘 다 맞는 말). 선택이 있으면 지금처럼 "선택한 행 내보내기"
- 기존 하네스가 옛 문구("로드된 N건만 내보냅니다")를 단정하면 **그 단정만** 새 문구로 고치고 보고에 목록을 적어라.
  위치·동작 단정은 건드리지 마라
- R29 의 선택 안내("로드된 N건이 선택됨 · 전체 M건")는 그대로

## 4. `which_component` — 떨어진 낱말도 찾는다

실측(사전 점검): 키워드를 질의 안의 연속 구절로만 맞춘다.

| 질의 | 지금 1순위 | 기대 |
|---|---|---|
| "옆에서 열리는 편집 패널" | Dialog (SheetContent 후보 없음) | SheetContent |
| "상품 이미지 여러 장 업로드" | Thumbnail | FileUpload |
| "상품명 검색" | Combobox | Input |

- 여러 낱말 키워드("옆 패널", "이미지 업로드")는 **모든 낱말이 질의에 있으면**(사이에 다른 말이 있어도) 연속 일치보다 낮은 점수로 맞춘다.
  고유 검색어가 있는 부품의 후보 조건(R36)에도 같은 기준
- Input 이 "검색" 질의를 받도록 키워드를 정리한다(R33 의 검색 칸 규칙과 맞게)
- 회귀: 내가 쓰는 대조 스크립트와 같은 방식으로 **기존 질의 전부**(모든 부품의 keywords·useWhen·purpose + 위 3개)의
  1순위 변화를 표로 보고하라. 의도하지 않은 1순위 변화는 0 이어야 한다. `match.test.mjs` 에 위 3개 질의 단정 추가
